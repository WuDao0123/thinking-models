# 09 创业与产品

适用于从 0 到 1、产品规划、需求验证、增长、单位经济。

### 精益创业 / MVP Lean Startup
- 核心：用最小可行产品快速验证假设，构建-测量-学习循环。
- 适用信号：新产品、新功能、不确定需求是否存在。
- 使用步骤：①写出核心假设（价值假设、增长假设） ②设计能验证假设的最小产品（可以是落地页、人工服务、Demo） ③定义成功指标 ④上线测量 ⑤坚持、调整或转向。
- 常见误区：MVP 做得太大；没有预设成功标准。

### 产品市场契合 Product-Market Fit
- 核心：产品满足了强烈市场需求，用户主动拉动增长。
- 适用信号：判断是否该扩张、该花钱推广。
- 使用步骤：①看留存曲线是否趋平 ②做 Sean Ellis 测试（"无法再用会很失望"≥40%） ③看自然增长和推荐比例 ④未达成则不要放大投放。
- 常见误区：用融资或投放制造的增长误判 PMF。

### 最危险假设优先 Riskiest Assumption Test
- 核心：先验证一旦错误就会让整个项目失败的假设。
- 适用信号：项目早期、资源有限。
- 使用步骤：①列出所有假设 ②按"不确定性 × 失败影响"排序 ③为最危险的假设设计最便宜的测试 ④通过后再处理下一个。
- 常见误区：先做最容易的部分。

### 妈妈测试 The Mom Test
- 核心：用户访谈中问过去的具体行为，而非对未来或你的想法的评价。
- 适用信号：需求调研、用户访谈。
- 使用步骤：①不提你的产品 ②问"上次遇到这个问题是什么时候？怎么解决的？花了多少钱/时间？" ③寻找承诺信号（付费、时间、介绍） ④忽略赞美和假设性回答。
- 常见误区：问"你会用吗？""你觉得这个好吗？"

### 客户开发 Customer Development
- 核心：客户发现 → 客户验证 → 客户创造 → 公司建设。
- 适用信号：B2B/新市场早期。
- 使用步骤：①走出办公室访谈 ②验证可重复的销售流程 ③再放大市场 ④最后扩建组织。
- 常见误区：跳过验证直接扩张。

### AARRR 海盗指标
- 核心：获客 Acquisition、激活 Activation、留存 Retention、变现 Revenue、推荐 Referral。
- 适用信号：增长诊断、找漏斗短板。
- 使用步骤：①为每层定义指标 ②测量各层转化率 ③找最差且影响最大的层 ④集中优化。（通常先修留存）
- 常见误区：留存差时加大获客。

### 北极星指标 North Star Metric
- 核心：一个最能代表用户获得核心价值、并驱动长期增长的指标。
- 适用信号：团队目标分散、指标太多。
- 使用步骤：①定义用户核心价值时刻 ②找能衡量该价值的频次/深度指标 ③拆解为输入指标 ④团队围绕输入指标行动。
- 常见误区：用收入或 DAU 这种结果指标当北极星。

### 成功指标与护栏指标体系 Success Metrics & Guardrails
- 核心：只优化一个指标会被古德哈特定律反噬（时长、点击、KPI 被"刷"出来，真实价值反而下降）。用"1 个代表真实价值的成功指标 + 若干不可突破的护栏指标（反向指标）+ 分群体检查 + 长期对照 + 自动回滚"来约束优化方向：成功指标必须提升，护栏任何一条被突破就不上线或回滚。
- 适用信号：A/B 测试与算法上线、推荐和增长策略、KPI/OKR 与绩效考核、激励制度、销售提成、客服效率指标；"数据涨了但投诉也涨了""指标好看但用户/员工不满意"。
- 使用步骤：①写出真实目标（用户价值、长期健康），选一个最贴近它的成功指标，必要时用满意度、留存等加权，而不是直接用时长或点击 ②列出优化该指标可能被牺牲的东西（质量、公平、安全、弱势群体、长期留存、合规），各设一个护栏指标与阈值 ③按关键群体拆分（新老用户、重度用户、未成年人、不同供给方），确认没有群体被显著伤害 ④保留长期对照组，测量新鲜感消退后的真实效应 ⑤在看到数据之前确定阈值、决策规则和否决权归属 ⑥设定自动回滚条件（如护栏连续 N 天被突破）和定期复盘。
- 常见误区：护栏只是"观察指标"没有约束力；看到数据后再改阈值；只看总体平均（辛普森悖论）；实验周期太短被新鲜感效应误导；把护栏否决权交给利益相关方中的增长团队自己。

### 卡诺模型 Kano Model
- 核心：需求分为基本型、期望型、兴奋型、无差异型、反向型。
- 适用信号：功能优先级、用户满意度。
- 使用步骤：①对每个功能问正向/反向问题（有它/没有它感受如何） ②归类 ③先满足基本型，持续提升期望型，选择性做兴奋型。
- 常见误区：兴奋型需求会随时间变成基本型。

### RICE 优先级
- 核心：分数 = 覆盖人数 Reach × 影响 Impact × 信心 Confidence ÷ 工作量 Effort。
- 适用信号：需求排期、功能取舍。
- 使用步骤：①为每项估四个值 ②计算分数 ③排序 ④用常识复核。
- 常见误区：数字拍脑袋还假装精确。

### MoSCoW 法
- 核心：Must / Should / Could / Won't 四级划分。
- 适用信号：范围控制、版本规划。
- 使用步骤：①列需求 ②Must 只放没有就不能发布的 ③Won't 明确写出 ④按级别排期。
- 常见误区：Must 太多。

### 上瘾模型 Hook Model
- 核心：触发 → 行动 → 多变奖励 → 投入，形成习惯。
- 适用信号：提升使用频率、留存、习惯养成产品。
- 使用步骤：①识别内部触发（情绪）和外部触发 ②降低行动门槛 ③设计多变奖励 ④让用户投入（数据、内容、关系）以加载下次触发。
- 常见误区：用于操纵损害用户。

### 跨越鸿沟 Crossing the Chasm
- 核心：早期使用者与早期大众之间存在鸿沟，需聚焦一个滩头市场。
- 适用信号：早期用户增长后停滞。
- 使用步骤：①识别滩头细分市场 ②提供完整解决方案 ③在该细分做到主导 ④以此为保龄球道扩展相邻市场。
- 常见误区：同时进攻多个细分。

### 创新扩散 Diffusion of Innovations
- 核心：采用者分为创新者 2.5%、早期采用者 13.5%、早期大众 34%、晚期大众 34%、落后者 16%。
- 适用信号：市场推广节奏、目标用户选择。
- 使用步骤：①判断当前处于哪类采用者 ②针对其动机调整信息（早期看新奇，大众看可靠和口碑） ③评估相对优势、兼容性、复杂度、可试用性、可观察性。
- 常见误区：用同一套话术对所有人群。

### 做不可规模化的事 Do Things That Don't Scale
- 核心：Paul Graham——早期手动获客、亲自服务、打磨体验。
- 适用信号：冷启动、早期用户少。
- 使用步骤：①一个个找用户 ②人工完成本该自动化的部分 ③深度服务前 10–100 个用户 ④从中学习再自动化。
- 常见误区：过早自动化。

### 默认存活 Default Alive
- 核心：按当前收入增长和支出，不再融资能否盈利？
- 适用信号：现金管理、要不要融资、招人节奏。
- 使用步骤：①算月支出、收入、增长率 ②预测盈亏平衡时间 vs 现金耗尽时间 ③若默认死亡，立即降本或调整。
- 常见误区：假设一定能融到钱。

### 1000 个铁杆粉丝 1000 True Fans
- 核心：凯文·凯利——创作者只需约 1000 个每年愿付约 100 美元的铁粉即可谋生。
- 适用信号：个人品牌、独立创作者、小众产品。
- 使用步骤：①定义铁粉画像 ②计算所需人数 = 目标收入 ÷ 每人年支出 ③建立直接关系（邮件、社群） ④提供持续价值与分层产品。
- 常见误区：忽略获取铁粉所需的巨大流量基数。

### 使用者-购买者分离 User–Buyer Split（决策单元 DMU）
- 核心：使用产品的人、付钱的人、做决定的人、能否决的人常常不是同一个人（老人用/子女买、孩子用/父母买、员工用/老板买、宠物用/主人买）。各方的"待完成工作"不同甚至相反，产品必须同时满足使用者愿意用、购买者愿意付。
- 适用信号：养老、儿童、教育、企业软件、医疗、宠物、礼品类产品；"用户很喜欢但没人买"或"买了但没人用"。
- 使用步骤：①列出决策单元角色：使用者、购买者、决策者、影响者、否决者（如护工、医生、IT 部门） ②分别写出各角色的任务、痛点、最怕的事 ③找出冲突点（如家属要信息、老人要隐私和零操作） ④设计化解方案：使用端极简、购买端看得见价值（汇总、报告、异常提醒） ⑤分别验证：使用者留存 + 购买者付费意愿，两者缺一不可。
- 常见误区：只访谈付钱的一方；把购买者的需求强加给使用者（功能越加越多、使用者弃用）；忽视否决者。

### 价值主张画布 Value Proposition Canvas
- 核心：客户任务、痛点、收益 ↔ 产品、止痛剂、增益创造器。
- 适用信号：定义产品价值、对齐用户需求。
- 使用步骤：①填客户侧 ②填产品侧 ③逐条匹配 ④未匹配的痛点是机会，未匹配的功能是浪费。
- 常见误区：凭想象填客户侧。

### 转向 Pivot
- 核心：保留已学到的东西，系统性改变一个维度（客户、问题、方案、渠道、模式）。
- 适用信号：指标长期停滞、假设被否定。
- 使用步骤：①回顾验证过和被否定的假设 ②确定改变哪个维度 ③保留有效资产 ④设新的验证周期。
- 常见误区：频繁转向不给时间；或拖太久不转。

### 单位经济 LTV / CAC Unit Economics
- 核心：单个客户终身价值应显著高于获客成本（通常 LTV/CAC ≥ 3，回收期 < 12 个月）。
- 适用信号：判断商业模式能否放大、投放是否盈利。
- 使用步骤：①LTV = 客单价 × 毛利率 × 平均生命周期 ②CAC = 获客总成本 ÷ 新客数 ③算比值和回收期 ④改善杠杆：提留存、提价、降 CAC。
- 常见误区：用收入而非毛利算 LTV；忽略自然流量混入。

### Rule of 40
- 核心：SaaS 公司增长率 + 利润率 ≥ 40%。
- 适用信号：评估软件公司健康度、增长与盈利权衡。
- 使用步骤：①计算两者之和 ②低于 40 时判断短板 ③按阶段调整。
- 常见误区：用于早期公司。

### 从后往前做 Working Backwards
- 核心：亚马逊——先写新闻稿和 FAQ，再开发产品。
- 适用信号：新产品立项、对齐团队。
- 使用步骤：①写发布新闻稿：客户是谁、问题、方案、好处 ②写外部 FAQ 和内部 FAQ ③如果新闻稿不打动人，就不做 ④以此倒推需求。
- 常见误区：写成功能列表。

### 用户故事地图 User Story Mapping
- 核心：按用户旅程横向排列活动，纵向排列细节和版本切片。
- 适用信号：规划 MVP 范围、需求梳理。
- 使用步骤：①列出用户主要活动 ②每个活动下列任务 ③横切出第一个能走通完整旅程的版本。
- 常见误区：按功能模块而非用户旅程切片。

### 激活时刻 Aha Moment
- 核心：用户首次体验到核心价值的时刻，与长期留存强相关。
- 适用信号：新用户流失、提升激活率。
- 使用步骤：①对比留存与流失用户的早期行为 ②找出强相关行为 ③重新设计引导流程让用户尽快到达。
- 常见误区：把相关当因果，需实验验证。

### 留存曲线 Retention Curve
- 核心：按批次看留存随时间的变化，曲线趋平说明有核心用户群。
- 适用信号：判断 PMF、评估产品改进效果。
- 使用步骤：①按注册周/月分批次 ②画留存曲线 ③看是否趋平及平台高度 ④比较新老批次判断改进。
- 常见误区：看总活跃数掩盖流失。
