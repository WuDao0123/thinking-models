# 13 问题解决与分析

适用于诊断原因、结构化拆解、复杂问题求解。

### 5 个为什么 5 Whys
- 核心：连续追问"为什么"约五次，从症状挖到根因。
- 适用信号：问题反复发生、只修表面。
- 使用步骤：①清晰描述问题 ②问为什么并基于事实回答 ③对答案继续问 ④直到找到可控的流程/系统原因 ⑤针对根因制定对策。
- 常见误区：停在"某人犯错"；只沿单一链条，忽略多因。

### 鱼骨图 Fishbone / Ishikawa
- 核心：从人、机、料、法、环、测等维度系统列出可能原因。
- 适用信号：原因复杂多样、团队头脑风暴诊断。
- 使用步骤：①问题写在鱼头 ②画主骨（6M 或自定义维度） ③每个维度下列原因 ④筛选最可能原因用数据验证。
- 常见误区：列完不验证。

### MECE 原则
- 核心：相互独立、完全穷尽地拆分问题。
- 适用信号：结构化分析、报告框架、问题拆解。
- 使用步骤：①选择拆分维度（流程、公式、对象、时间） ②检查是否有重叠 ③检查是否有遗漏 ④必要时加"其他"。
- 常见误区：为了 MECE 牺牲洞察。

### 指标拆解树 Driver Tree（驱动因子树）
- 核心：把结果指标拆成相乘或相加的驱动因子（如 营业额 = 进店人数 × 转化率 × 客单价），逐层定位是哪个因子变了；已知不变的因子可直接排除，并据此检验方案是否作用于正确的因子。
- 适用信号：营收/利润/增长/成本等数字指标异常；"为什么下降了"；多个方案争论不休；需要找最大杠杆因子。
- 使用步骤：①写出指标的数学恒等式（乘法优先，便于看变化比例） ②先核对数据口径（统计方式、是否含退款/抽成/折扣、计数是否混入无效样本） ③用已知数据代入，排除不变的因子，算出变化的因子须满足的关系（如"转化率×客单价=0.7"） ④对变化的因子继续往下拆（客单价 = 件数 × 件单价 − 折扣） ⑤按时间、渠道、品类、人群等维度切分，找变化集中处 ⑥把每个候选方案映射到它作用的因子上，淘汰作用于不变因子的方案 ⑦对关键因子做敏感性分析，确定实验优先级。
- 常见误区：拆解不是恒等式（遗漏因子或重复计算）；跳过数据口径核对；只拆一层就下结论；把因子间的相互影响当作独立（如降价同时影响转化率和客单价）。

### 议题树 / 逻辑树 Issue Tree
- 核心：把核心问题逐层拆解为子问题，直至可回答。
- 适用信号：复杂问题无从下手。
- 使用步骤：①写清核心问题（具体、可回答） ②按 MECE 拆分为 2–5 个子问题 ③继续拆分到可分析层 ④为每个末端问题确定分析方法和数据。
- 常见误区：拆解维度混乱。

### 实验设计与可重复性 Experimental Design & Replication
- 核心：一个效应只有在排除测量误差、操作者、批次/样本、环境/实验室差异和选择性报告之后，才可信。通过对照、随机化、盲法、预先登记和多因素设计，把这些来源分离开；早期结果往往偏高（效应衰减、赢家诅咒），独立复现是最关键的一级证据。
- 适用信号：科研结果、A/B 测试、产品或营销实验、医学/健康说法、新工艺试产；"初步结果很惊艳""换个人/换批次就不灵了""别人复现不出来"。
- 使用步骤：①拆解测量值：真实效应 + 批次/样本 + 操作者/执行 + 测量误差 + 选择性报告 ②审计口径与全部原始数据（含失败、中途放弃的样本），统一指标定义 ③每轮实验放入同条件对照组，看相对差异以抵消漂移 ④用多因素设计分离来源（如 操作者 × 批次 × 实验室），每格有足够重复 ⑤预先写好方案、样本量和判定标准，分析时盲法，全部结果计入 ⑥安排独立复现：同材料不同实验室、同方法不同材料，区分"方法转移失败"与"效应不存在" ⑦对异常来源（如某批次）做成分或特征分析——差异本身可能是新发现。 ⑧政策与现场干预的归因设计：采用"前后-对照-干预"（BACI：干预前测基线，并保留可比的对照区域/人群，比较干预区与对照区的变化差）；多项措施时在不同区域错开或交叉实施（分区错开、阶梯式推开），才能分离各措施效果；按措施对应的多个指标分别评估，并考虑生态、行为等的时间滞后。
- 常见误区：用同一人、同一批次的重复次数代替独立证据；只报告成功的那几次；中途看数据决定是否继续（p-hacking）；把复现失败直接等同于效应不存在（也可能是方法转移问题）；在独立复现前公开宣传；政策评估中没有对照组就把前后变化全归功（或归咎）于某一项措施；多项措施同时同地上马导致无法归因。

### 假设驱动 Hypothesis-Driven Problem Solving
- 核心：先提出最可能的答案，再收集数据证实或证伪，而非漫无目的收集。
- 适用信号：时间紧、数据多、需要快速形成结论。
- 使用步骤：①基于经验提出初始假设 ②列出若假设成立必须为真的条件 ③设计分析逐条检验 ④证伪就修正假设。
- 常见误区：只找支持证据（确认偏差）。

### 根因分析 Root Cause Analysis
- 核心：系统地区分症状、近因和根本原因。
- 适用信号：事故、质量问题、重大失误。
- 使用步骤：①收集事实时间线 ②识别因果链 ③区分直接原因、促成因素、根本原因 ④为根因设计纠正和预防措施 ⑤验证效果。
- 常见误区：找到"替罪羊"就停止。

### 分而治之 Divide and Conquer
- 核心：把大问题拆成独立的小问题分别解决再组合。
- 适用信号：问题庞大、调试定位（二分法）。
- 使用步骤：①找可独立的子问题 ②逐个解决 ③定位故障时用二分法排除一半范围 ④组合并验证。
- 常见误区：子问题之间有耦合。

### 抽象与具体化 Ladder of Abstraction
- 核心：在抽象（原理、模式）和具体（例子、细节）之间上下移动。
- 适用信号：思路卡住、沟通不清、找通用方案。
- 使用步骤：①往上问"为什么/这属于哪类问题" ②往下问"具体怎么做/举个例子" ③在合适层级解决问题。
- 常见误区：停留在单一层级。

### TRIZ 发明问题解决理论
- 核心：大多数发明问题可归为矛盾，可用 40 个发明原理解决（分割、反向、预先作用、动态化、自服务等）。
- 适用信号：技术矛盾（提升 A 必然恶化 B）、工程/产品设计难题。
- 使用步骤：①把问题表述为矛盾（技术矛盾或物理矛盾） ②查找对应发明原理 ③类比生成方案 ④追求"理想最终结果"（不增加成本就实现功能）。
- 常见误区：机械套用原理。

### PDCA 循环
- 核心：计划 Plan → 执行 Do → 检查 Check → 处理 Act，持续改进。
- 适用信号：流程优化、质量改进、反复迭代。
- 使用步骤：①设定目标和计划 ②小范围执行 ③测量对比 ④标准化有效做法或调整 ⑤进入下一循环。
- 常见误区：跳过检查。

### A3 问题解决
- 核心：在一张 A3 纸上完成：背景、现状、目标、根因、对策、计划、跟进。
- 适用信号：需要结构化且共享的问题解决报告。
- 使用步骤：按七栏顺序填写，用图表代替文字，与相关方迭代确认。
- 常见误区：写成冗长文档。

### 波利亚四步法 Pólya's How to Solve It
- 核心：理解问题 → 制定计划 → 执行计划 → 回顾。
- 适用信号：数学题、技术难题、陌生问题。
- 使用步骤：①未知是什么？已知是什么？条件是什么？ ②见过类似问题吗？能否简化/特例化/倒推？ ③执行并检验每一步 ④结果能否用其他方法验证？能否推广？
- 常见误区：不理解问题就动手。

### 约束放松 Constraint Relaxation
- 核心：暂时去掉某个约束，看能否找到方案，再把约束加回来。
- 适用信号：问题看似无解。
- 使用步骤：①列出所有约束 ②逐个问"如果没有这个约束会怎么做？" ③从解中找能在约束下实现的部分 ④检验约束是否真实存在。
- 常见误区：忘了把约束加回来。

### 类比推理 Analogical Reasoning
- 核心：从结构相似的已解决问题中借用方案。
- 适用信号：新问题、跨领域创新。
- 使用步骤：①抽象出问题的结构 ②在其他领域找相同结构 ③迁移方案 ④检查关键差异处是否失效。
- 常见误区：表面相似误当结构相似。

### 竞争假设分析 Analysis of Competing Hypotheses (ACH)
- 核心：来自情报分析（Heuer）。不先锁定一个答案再找支持证据，而是列出所有能解释现象的假设，用"假设 × 证据"矩阵按诊断性（能否区分假设）评估每条证据，重点寻找能推翻假设的证据；结论以"最难被推翻的假设"和分级置信表述呈现。配合证据保管链，确保关键证据完整、可追溯。
- 适用信号：内部调查（泄密、舞弊、违规）、事故与故障根因、情报与新闻核实、医学鉴别诊断、谣言判断；"大家都觉得是他""证据看起来都指向一个人"；时间压力下要求尽快定性。
- 使用步骤：①列出所有合理假设（含"系统原因""外部原因""多人组合"），不急于排除 ②保全原始证据：完整导出、计算哈希、记录取得人/时间/方法，用副本分析；截图与转述只作线索 ③列出证据并评估可靠性（来源、完整性、时间校准、是否来自利益相关方） ④填写矩阵：每条证据对每个假设是"一致 / 不一致 / 无关"；在所有假设下都会出现的证据诊断性为零，降低权重 ⑤按"最能区分假设"给待获取证据排序，优先获取 ⑥以"不一致证据最少"的假设为暂定结论，并说明哪些证据会推翻它 ⑦分层表述：区分"系统/账号做了什么"与"人做了什么"，用分级置信词（已确认 / 很可能 / 无法判断 / 不成立）报告，写明证据缺口 ⑧指定专人为非主流假设辩护，隐去人名评估证据，减少声誉偏见。
- 常见误区：先定嫌疑人再找证据；用动机代替行为证据；把在所有假设下都成立的证据当作有力证据；截图当证据；把账号行为等同于个人行为；时间压力下给出超出证据的结论；调查人员与当事人有利益冲突。

### 凯普纳-特里戈法 Kepner-Tregoe
- 核心：情境评估、问题分析（是/不是对比）、决策分析、潜在问题分析。
- 适用信号：故障排查、系统性决策。
- 使用步骤：①描述问题"是什么/不是什么、在哪/不在哪、何时/何时不、多大" ②找出差异点 ③推测原因并用差异验证 ④确认真正原因。
- 常见误区：跳过"不是"的对比。

### 小黄鸭调试 Rubber Duck Debugging
- 核心：把问题逐行讲给别人（或一只鸭子）听，往往自己就发现问题。
- 适用信号：卡住、思维混乱。
- 使用步骤：①从头完整描述问题和你的假设 ②每一步说明为什么 ③注意自己说不顺的地方。
- 常见误区：跳过"显而易见"的步骤。

### 帕累托分析 Pareto Analysis
- 核心：找出导致 80% 问题的 20% 原因，优先解决。
- 适用信号：问题很多、资源有限、客诉分析。
- 使用步骤：①收集问题和频次/影响 ②排序并算累计百分比 ③聚焦前几项。
- 常见误区：忽略低频但致命的问题。

### 问题重构 Problem Reframing
- 核心：很多时候问题定义错了；改变问题的表述往往直接带来解法。
- 适用信号：方案都不满意、"电梯太慢"类问题。
- 使用步骤：①写下原问题 ②问"真正目标是什么？" ③换视角重述（用户、时间、规模、反向） ④选择最有解的表述。
- 常见误区：急于解决眼前定义的问题。

### 逆向工作 Work Backwards from Goal
- 核心：从理想结果倒推需要的前置条件。
- 适用信号：目标明确但路径不清、规划。
- 使用步骤：①定义终态 ②问"实现它的前一步必须是什么？" ③逐步倒推到当前 ④得到路径和里程碑。
- 常见误区：终态定义模糊。

> 相关：敏感性分析见 21-math.md，用于确定哪个变量对结论影响最大。

### 二分法排查 Binary Search Debugging
- 核心：每次检验把问题范围缩小一半。
- 适用信号：定位故障、找哪次变更引入问题。
- 使用步骤：①确定已知正常与异常的边界 ②检验中点 ③缩小范围 ④重复直至定位。
- 常见误区：问题不可复现时失效。
